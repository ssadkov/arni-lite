# Поиск, картинки, MCP и агент для компьютера

Дата: 13 ноября 2026 года. Статус: разбор по коду, не решение о реализации и не проверка живого API.

Основание: `ArniLite` на 13 ноября 2026 (`LocalToolHost`, `ToolCalls.cs`, `Agent.cs`, `ArniApiClient`, ADR 001 и 003, `docs/ARNI_LITE_WINDOWS_SPEC.md`, `docs/LANGUAGES_MEDIA.md`) и `arni-backend` на ту же дату (`POST /api/web-search`, `POST /api/images/generations`, `src/lib/webSearch.ts`, `src/lib/imageGeneration.ts`, `src/lib/llm/vision.ts`, `src/lib/desktopAuth.ts`). В ArniCode те же API уже вызываются из `arniWebSearch.ts` и `arniImageGeneration.ts`. Бэкенд в этом разборе не вызывался.

## Вывод

Web search и генерация картинок ложатся в текущий цикл инструментов и не мешают запуску на Windows 7. Общий MCP-хост, как в ArniCode, на эту сборку не переносится. Презентации на Windows 7 делаются своим инструментом Open XML внутри процесса, а не браузером и не Node.

Рекомендация: в сборку для Windows 7 добавить поиск и картинки обычными инструментами. MCP и браузер держать отдельным модулем, который загружается только на Windows 10 и новее и отсутствует в процессе на Windows 7 и Server 2012. Так уже задуман будущий браузер в `docs/LANGUAGES_MEDIA.md`: опционально и без влияния на лёгкий старт.

Любая новая зависимость должна отсутствовать на диске и не мешать старту exe. Whisper в 0.1.2 уже сделан так: качается только по запросу. Поиск, картинки и Open XML в этот шаблон укладываются. Node, WebView2 и локальные MCP-серверы — нет.

## Что уже есть

Lite — агент одной папки. В режиме агента модель получает пять инструментов: `list_files`, `read_file`, `search_text`, `propose_file_change`, `run_command`. Цикл собирает tool calls, пишет результат обратно в историю и останавливается на лимитах: 12 раундов модели, 30 вызовов, 15 минут. Запись файла и команда идут через подтверждение и журнал. Повтор того же побочного действия после отказа в этом ходе блокируется.

Команда — `powershell.exe` или `cmd`, без песочницы, от имени текущего пользователя. Интерактивного терминала нет. Спека выносит за MVP браузер, MCP, плагины и правку DOCX/XLSX/PDF как текста. `propose_file_change` пишет только текст целиком, поэтому PPTX и PNG через него не собрать.

Сеть клиента — `HttpClient` на .NET Framework 4.8. На системах старше Windows 10 процесс сам включает TLS 1.2 (`TlsBootstrap`). Тот же JWT, который Lite получает при входе (`encryptJWT` в desktop auth), бэкенд принимает на поиске и генерации картинок (`mediaUser` → `decryptJWT`).

Запуск самого exe на Windows 7 SP1 и Windows Server 2012 по-прежнему не доказан. Это записано в README и ADR 001. Новые инструменты не заменяют эту проверку.

## Web search

Подтверждено в бэкенде. `POST /api/web-search` с Bearer JWT отдаёт до пяти результатов Exa: заголовок, URL, короткий сниппет. Ключ Exa живёт только на сервере (`searchExaWeb`). Нет ключа — ответ 503 `search_unconfigured`. Клиент ходит только на `api.arnion.ru`, тот же хост, что и чат.

В Lite это новый read-only инструмент рядом с `search_text`: схема, один POST, JSON обратно модели, обрезка вывода. Подтверждение на каждый запрос не нужно: спека уже разрешает read-only после выбора проекта, а поиск от папки не зависит. Оценка объёма: один-два дня вместе с тестами. Новый рантайм не требуется.

Сниппет — не страница. Дочитывание URL в инструментах v1 запрещено спекой (раздел 9.1). На Windows 7 произвольный HTTPS ненадёжен: старое хранилище сертификатов, нет TLS 1.3. Если понадобится текст страницы, его забирает бэкенд и отдаёт клиенту готовым. Такого маршрута сейчас нет.

Открытая зависимость: в проде должен быть `EXA_API_KEY`. По репозиторию это не проверить.

## Генерация картинок

Подтверждено в бэкенде и уже сделано в ArniCode. Контракт:

- `POST /api/images/generations`, заголовок `Idempotency-Key` длиной 16–100 символов `[a-zA-Z0-9_-]`, тело `{ prompt, model, aspect_ratio, n: 1 }`.
- Две модели в `us-west-2`: Stable Image Core (`stability.stable-image-core-v1:1`, $0.04) и SD 3.5 Large (`stability.sd3-5-large-v1:0`, $0.08), когда на картинке нужен читаемый текст. Сервер модель сам не выбирает.
- Ответ — id и цена. Байты забираются отдельным `GET /api/images/{id}`.
- Повтор с тем же ключом и тем же телом не списывает второй раз. Другое тело с тем же ключом — 409.
- Кириллица отклоняется до вызова модели (`image_prompt_language`, проверено 11 ноября 2026). Промпт на английском.
- Нужны бюджет аккаунта, `ARNI_IMAGE_GENERATION_ENABLED=true` и отдельный ключ `AWS_BEARER_TOKEN_BEDROCK_IMAGES`. Иначе 503.

В клиенте: инструмент с относительным путём `*.png` внутри проекта, ключ идемпотентности как в ArniCode (хеш корня проекта, пути, промпта, модели и пропорций; SHA-256 hex укладывается в лимит ключа), таймаут около 240 секунд на генерацию и 60 на скачивание. Сейчас `HttpClient` у Lite без таймаута, поэтому лимит стоит на самом вызове, а не на клиенте целиком. Запись идёт через тот же журнал, что и правка файла: существующий файл не затирать, путь не выпускать из папки проекта (junction тоже). Показ — обычный WPF `BitmapImage`. Видеоплеер из 0.1.2 для PNG не нужен. PNG в WPF на Windows 7 декодируется штатно.

Оценка объёма: несколько дней. Новый рантайм не требуется.

Модель получившуюся картинку не увидит. `ChatMessage.Content` в Lite — строка, а бэкенд принимает картинку только как `image_url` с data-URL PNG или JPEG в сообщении пользователя или в результате инструмента: до 20 изображений, суммарно до 2,5 МБ, сторона до 8000 px (`src/lib/llm/vision.ts`). Это отдельное изменение сериализатора. Оно нужно, только если агент должен сам смотреть на результат.

Открытая зависимость: включены ли флаги генерации в проде на 13 ноября 2026. По коду это не видно. Документ `arni-backend/docs/bedrock-media-and-costs.md` отдельно отмечает, что наличие модели в каталоге не доказывает право конкретного runtime-ключа.

## MCP

В ArniCode MCP — хост двух видов серверов: локальный процесс по stdin/stdout и удалённый HTTP/SSE (`McpServerType` в `mcpPlatformTypes.ts`). Поиск и картинки там не MCP. Это обычные инструменты агента, которые сами ходят в API Arni.

Полезные MCP-серверы почти все запускаются через современный Node или Python. Текущий Node на Windows 7 не работает. Вложить в Lite Node, Python или хост MCP из VS Code значит либо не запуститься на Windows 7, либо тащить старый рантайм, на котором сегодняшний MCP SDK не живёт. Спека (раздел 3.3) уже вынесла MCP-серверы и плагины за MVP.

Что совместимо с текущей сборкой `net48`:

- Удалённый MCP по HTTP/SSE можно говорить из того же `HttpClient`. Это JSON-RPC, без нового процесса. OAuth таких серверов — отдельная работа поверх уже существующего входа через внешний браузер.
- Локальный stdio технически похож на уже существующий запуск PowerShell, но сам сервер должен запускаться на Windows 7. Для каталога MCP это редкость.

Полный хост — жизненный цикл процесса, OAuth, ресурсы, схемы десятков инструментов, подтверждение каждого вызова, укладка в лимит 30 вызовов — это недели. На Windows 7 он всё равно не откроет обычный набор серверов.

Обратный смысл «MCP-сервер» — чтобы Claude Desktop или Cursor вызывали Lite. Локальный JSON-RPC на `HttpListener` или stdin в net48 возможен и старт не ломает. Наружу отдаются уже существующие файлы и команды. Само приложение от этого презентации делать не научится.

## Агент для компьютера и презентации

Сейчас агент умеет читать и переписывать текст в одной папке и выполнять одну неинтерактивную команду после подтверждения. Оболочка формально может вызвать PowerPoint через COM, если Office установлен. Это не проверенный сценарий. На чистой Windows 7 это PowerShell 2.0. Поведение job object при остановке дерева процессов на Windows 7 в ADR 003 не доказано, поэтому презентации не стоит строить на длинном PowerShell.

Рабочий путь для презентаций:

1. Инструмент внутри процесса, который собирает PPTX, DOCX и XLSX как Open XML библиотекой под `netstandard2.0`. Office на машине не нужен, отдельный exe не нужен, x86 и x64 получают один и тот же управляемый код. Картинки на слайды кладёт инструмент генерации. Оценка: средний объём, больше поиска и меньше MCP. Библиотека даёт файл. Структура и вкус слайдов остаются за моделью.
2. Навык «структура колоды» в системном тексте агента. В библиотеке навыков бэкенда на эту дату монтаж и текст, не слайды.
3. Подтверждение на сессию уже есть (`AllowSideEffectsForSession`). Без него колода из двадцати шагов превращается в двадцать диалогов.

После презентаций, по приоритету:

- Чтение страницы после поиска, на стороне бэкенда.
- Вложения PNG/JPEG в запрос, чтобы модель с `vision: true` видела скриншот или слайд. Захват экрана через Win32 на Windows 7 возможен. Клики мышью и ведение чужих окон — другой проект. Спека его не включает. WebView2 на Windows 7 нет.
- Двоичные файлы и удаление как отдельные инструменты.
- Долгая команда с журналом и кнопкой «стоп». Это уже пункт P1 в спеке. Интерактивный терминал туда не входит.

Смена интерфейса не заставит современные сторонние программы работать на старой ОС. Это уже сказано в разделе 3.3 спецификации.
